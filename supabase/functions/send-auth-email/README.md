# GAME ON Gmail API Auth Email Sender

This Supabase Edge Function replaces Supabase Auth's SMTP delivery with the Gmail API for the GAME ON sender account:

- Sender: contactgameoninternational@gmail.com
- Display name: GAME ON
- Required Google OAuth scope: https://www.googleapis.com/auth/gmail.send

The function verifies Supabase's signed Send Email Auth Hook request before reading the message payload. It creates the Supabase verification URL from the one-time token hash, sends both HTML and plain-text email bodies through Gmail API, and logs only the action type and provider acceptance/failure code. It never logs recipients, OTPs, verification links, OAuth tokens, or secrets.

Gmail API acceptance is not proof that the recipient's inbox received the message. Gmail may still reject, bounce, or place a message in spam after accepting it. The function reports provider acceptance/rejection; it does not claim inbox delivery.

## Google Cloud setup

A parent/guardian who manages the GAME ON sender account should complete these steps while signed into contactgameoninternational@gmail.com.

1. Create or select a Google Cloud project and enable the Gmail API.
2. Configure the OAuth consent screen for an external app. Add the sender mailbox as a test user while developing.
3. Create a Web application OAuth client. Add this authorized redirect URI if using Google's OAuth Playground to issue the one-time refresh token: https://developers.google.com/oauthplayground
4. Request only this scope: https://www.googleapis.com/auth/gmail.send
5. Open https://developers.google.com/oauthplayground. In its settings, enable use of your own OAuth credentials, enter the OAuth client ID and secret, and request offline access. Authorize the exact GAME ON sender mailbox and exchange the authorization code for tokens. Copy the refresh token privately.

Important Google OAuth limitations:
- gmail.send is a sensitive Gmail scope and Google may require OAuth app verification before wider production use.
- An external OAuth app left in Testing mode issues refresh tokens that expire after seven days. Do not treat Testing mode as a permanent production setup.
- For durable production use, publish the OAuth app appropriately and complete any Google verification that applies. Google can revoke a refresh token, so the sender must handle re-authorization if that happens.

## Supabase function secrets

In Supabase Dashboard → Edge Functions → Secrets, add these values. Do not commit them to GitHub or paste them into chat.

| Secret | Value |
| --- | --- |
| GMAIL_OAUTH_CLIENT_ID | OAuth client ID from Google Cloud |
| GMAIL_OAUTH_CLIENT_SECRET | OAuth client secret from Google Cloud |
| GMAIL_OAUTH_REFRESH_TOKEN | Refresh token issued for the GAME ON sender |
| GMAIL_SENDER_EMAIL | contactgameoninternational@gmail.com |
| GMAIL_SENDER_NAME | GAME ON |
| SEND_EMAIL_HOOK_SECRET | The complete signing secret generated by Supabase Auth Hooks |

SUPABASE_URL is supplied to Supabase Edge Functions automatically.

## Deploy and connect the hook

Deploy the function with JWT verification disabled because it authenticates the request using the Supabase Standard Webhooks signature:

    supabase functions deploy send-auth-email --project-ref viwczhmthlyagqwcrgrt --no-verify-jwt

Then open Supabase Dashboard → Authentication → Hooks and create a Send Email hook:
- Hook type: HTTPS
- URL: https://viwczhmthlyagqwcrgrt.supabase.co/functions/v1/send-auth-email
- Generate a new signing secret and save the complete value as SEND_EMAIL_HOOK_SECRET in Edge Function Secrets.
- Enable the Send Email hook only after all six secrets are saved and the function is deployed.
- Keep the email provider enabled. With the Send Email hook enabled, Supabase uses the hook instead of SMTP for Auth messages.

The function is intentionally not configured as an active hook by this source change alone. Do not enable it until the OAuth client, refresh token, hook secret, and deployed function have all been checked.
